## Key Code Changes

### hook_handler.py — env var + envelope format
- Priority: CLI arg > `CLAUDE_CODE_FILEPATH` env var > stdin JSON
- Handles Claude Code hook envelope: `{"tool_input": {"file_path": "..."}}`

### installer.py — idempotent settings.json manipulation
- Marker-based idempotency: `src.ingest.hook_handler` and `synapse-context-inject`
- Append-only: never reorders existing hooks
- `sys.executable` for Python path resolution (no hardcoded venv paths)

### synapse-context-inject.sh — lightweight daemon check
- `kill -0` PID check (instant, no Python startup)
- Three output states: running, vault exists but daemon off, no vault (silent)
- JSON format: `{"hookSpecificOutput":{"hookEventName":"PreToolUse","additionalContext":"..."}}`

## Architecture Decisions

1. **Bash script for context injection** (not Python) — avoids ~200ms Python startup on every Read/Glob/Grep call. The script runs in ~5ms.
2. **Marker-based idempotency** — instead of exact-match comparison (fragile), search for unique marker strings in hook commands. Allows timeout or matcher changes without breaking idempotency.
3. **Append-only hook registration** — never reorders existing hooks in settings.json. Safer for user's existing configuration.
4. **Three-state context injection** — the bash script doesn't just binary "available/unavailable". It distinguishes daemon-running vs vault-exists-but-daemon-off vs nothing-at-all, giving appropriate guidance at each level.
