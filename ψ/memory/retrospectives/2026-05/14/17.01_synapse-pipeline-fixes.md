## Honest Feedback

1. **Docker build context confusion wasted 10 minutes.** The first rebuild used cache for `src/` because the docker-compose context was `../synapse` but I ran `docker build` from the synapse directory directly. The image names differed (`synapse:latest` vs `infra-oracle-synapse`). I should have checked the docker-compose build context first instead of assuming `docker build -t synapse` was sufficient.

2. **`curl` JSON parsing artifact was a red herring.** For 5 minutes I thought the server was returning malformed JSON because `curl` showed unquoted keys (`id: string`). It was actually a display artifact — `python3 -m json.tool` worked fine. I spent energy investigating the wrong thing. The lesson: verify with multiple tools before assuming the server is broken.

3. **The `/learn --deep` agents took ~5 minutes each but I had to poll/wait repeatedly.** The notification system works but the "wait with background bash + check" pattern is clunky. I should have just waited for the completion notifications instead of chaining `sleep` commands. Better: trust the async system and work on something else while agents run.

## Lessons Learned

1. **Auto-extract metadata at ingestion boundaries.** Concepts, tags, links — if the content contains them, extract them. Don't require manual passing. The `push_text()` defaulting to `extract_concepts(content)` when `concepts=None` is the right pattern.

2. **Frontend re-renders need explicit state updates.** A callback that updates a local variable but doesn't call `setState` is invisible to React. The `onSources` fix is a pattern: any async data that arrives before the main stream needs its own state trigger.

3. **Patch the right module in tests.** `startup()` imports `restore_registry_backup` from `src.registry` locally, not at module level. Patching `src.main.restore_registry_backup` fails because the name isn't bound in `src.main` — patch `src.registry.restore_registry_backup` instead.
